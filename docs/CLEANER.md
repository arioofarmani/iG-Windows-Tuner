# iG Windows Tuner cleaner rules

> Generated by `tools\Build-Docs.ps1` from `data\cleaner\*.json`. Do not edit by hand.

44 allow-list rules. Every rule names the folders it may clean; nothing outside them is ever touched. The cleaner always scans first (read-only) and then deletes only the files that scan found, re-checking each file right before it is deleted.

## Safety model

- Allow-list only: a file is deleted only if its canonical path lies strictly inside one of the rule's roots, and the roots are resolved again at clean time.
- Paths are canonicalized (`..`, 8.3 short names) before any check; relative, UNC and device paths are refused.
- A hard denylist in the deletion primitive protects drive roots, Windows (except Temp, the update download cache, CBS/DISM logs and crash dumps), Program Files (except the Steam shader cache, logs and dumps), ProgramData roots, Defender folders, profile roots, Documents, Desktop, Pictures, Music, Videos, Saved Games, OneDrive and the Downloads folder (opt-in rule only).
- Browser profiles: only cache folders (Cache, Code Cache, GPU and shader caches, cache2) are cleaned. Cookies, history, passwords and extensions are never touched.
- Junctions, symbolic links and mount points are never followed or deleted; each file's parent chain is re-checked for reparse points right before deletion.
- Cloud placeholders and offline files are skipped, so cleaning never triggers a download.
- Files that changed since the scan, are younger than the rule's minimum age, are in use, or are read-only are skipped.
- Only single files and empty folders are deleted; there is no recursive delete. Apps are never closed (rules that need an app closed are skipped while it runs). Services are stopped only for rules that declare them and are always restarted.
- Every deleted path is written to `Logs\Cleaner-<time>.jsonl`.

### Servicing logs (CBS and DISM)

`clean.cbs-logs` | Standard | Tier B | method files | reversible: none

*Removes old servicing log files and their compressed archives (admin). The three newest files are kept.*

Deletes old CBS and DISM log files and their .cab archives. The newest three files are kept so recent servicing problems can still be diagnosed, and logs in use are skipped. Deleted logs cannot be restored.

**Folders:**

- `%SystemRoot%\Logs\CBS`
- `%SystemRoot%\Logs\DISM`

**Filters:** older than 72 h; only *.log, *.cab; keeps the newest 3.

### Component store cleanup (DISM)

`clean.component-store` | Advanced | Tier A | method dism | reversible: none

*Runs DISM StartComponentCleanup to remove superseded update components (admin). Can take several minutes.*

Uses Repair-WindowsImage -StartComponentCleanup, the supported way to shrink the WinSxS component store. It removes superseded component versions that Windows would also clean on its own schedule. iG Windows Tuner never deletes inside WinSxS directly. Updates installed in the last 30 days stay uninstallable.

**Side effects:** Older superseded update versions can no longer be restored.

**Sources:** <https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder>

### Component store cleanup with /ResetBase

`clean.component-store-resetbase` | Expert | Tier A | method dism | reversible: none

*DISM cleanup with ResetBase: frees the most space but makes all installed updates permanent (no uninstall).*

Runs StartComponentCleanup with ResetBase, which removes every superseded component version. All currently installed updates become permanent and cannot be uninstalled. Use it only on a stable system you do not need to roll back.

**Side effects:** Installed updates can no longer be uninstalled.

**Sources:** <https://learn.microsoft.com/en-us/windows-hardware/manufacture/desktop/clean-up-the-winsxs-folder>

### Delivery Optimization cache

`clean.delivery-optimization` | Standard | Tier A | method deliveryOptimization | reversible: none

*Empties the Delivery Optimization cache with Windows' own cmdlet (needs admin). Updates still download normally.*

Runs Delete-DeliveryOptimizationCache, the supported way to empty the cache that Windows Update and Store downloads use. Windows refills it only as needed. Nothing to revert: the cache is rebuilt automatically.

**Side effects:** Content in the cache is downloaded again if it is needed later.

**Sources:** <https://learn.microsoft.com/en-us/powershell/module/deliveryoptimization/delete-deliveryoptimizationcache>

### Old driver packages

`clean.driver-store` | Expert | Tier A | method driverStore | reversible: none

*Removes older third-party driver versions not used by any device, via pnputil without /force (admin).*

Finds third-party driver packages that have a newer version of the same package installed and are not bound to any present device. It removes them with pnputil /delete-driver without /force, so Windows refuses anything in use. Rolling a device back to a removed version then needs the old installer.

**Side effects:** Device Manager 'Roll Back Driver' can no longer return to the removed versions.

**Sources:** <https://learn.microsoft.com/en-us/windows-hardware/drivers/devtest/pnputil-command-syntax>

### Previous Windows installation (Windows.old)

`clean.windows-old` | Expert | Tier A | method guidance | reversible: full

*Shows the size of Windows.old and upgrade leftovers. Remove them in Settings to keep Windows' own rollback logic.*

Reports the size of C:\Windows.old and the upgrade staging folders. Removing them deletes your ability to go back to the previous Windows version, so iG Windows Tuner hands this to Windows itself: Settings > System > Storage > Temporary files > Previous Windows installation(s).

**Side effects:** Removing it (in Settings) makes the upgrade permanent.

**Folders:**

- `C:\Windows.old`
- `C:\$WINDOWS.~BT`
- `C:\$WINDOWS.~WS`

*Note:* Guidance only: use Settings > System > Storage > Temporary files > Previous Windows installation(s).

**Sources:** <https://support.microsoft.com/en-us/windows/delete-your-previous-version-of-windows-f8b26680-e083-c710-b757-7567d69dbb74>

### Windows Update download cache

`clean.windows-update-cache` | Advanced | Tier A | method files | reversible: none

*Clears downloaded update files; stops and restarts Windows Update, BITS and DO (admin). Fixes stuck downloads.*

Deletes the contents of C:\Windows\SoftwareDistribution\Download, which is Microsoft's documented step for resetting stuck Windows Update downloads. The Windows Update, BITS and Delivery Optimization services are stopped first and always restarted afterwards. Pending updates download again.

**Side effects:** Updates that were already downloaded are downloaded again.

**Folders:**

- `%SystemRoot%\SoftwareDistribution\Download`

**Filters:** stops and restarts wuauserv, bits, dosvc.

**Sources:** <https://learn.microsoft.com/en-us/troubleshoot/windows-client/installing-updates-features-roles/additional-resources-for-windows-update>

### Docker Desktop disk usage

`clean.dev.docker` | Expert | Tier A | method guidance | reversible: full

*Shows how much space Docker Desktop's disk image uses. Clean it with 'docker system prune' instead of deleting files.*

Reports the size of Docker Desktop's WSL disk image. Deleting the file would destroy all images, containers and volumes, so iG Windows Tuner only shows the size. Use 'docker system prune' and Docker Desktop's Troubleshoot page to reclaim space.

**Folders:**

- `%LOCALAPPDATA%\Docker\wsl`

*Note:* Guidance only: run 'docker system prune' (and Docker Desktop > Troubleshoot > Clean / Purge data) to reclaim space.

**Sources:** <https://docs.docker.com/reference/cli/docker/system/prune/>

### Gradle caches

`clean.dev.gradle` | Expert | Tier B | method files | reversible: none

*Clears the Gradle build cache and downloaded dependencies. The next build downloads everything again.*

Deletes ~\.gradle\caches, which holds downloaded dependencies and build-cache entries. Projects are not touched, but the next build is much slower and needs network access. Stop Gradle daemons first.

**Side effects:** The next Gradle builds are slow and need network access.

**Folders:**

- `%USERPROFILE%\.gradle\caches`

### Maven local repository

`clean.dev.maven` | Expert | Tier B | method files | reversible: none

*Clears the Maven local repository (~\.m2\repository). The next build downloads all dependencies again.*

Deletes the Maven local repository. Artifacts you installed locally with 'mvn install' are removed too and must be rebuilt. The next build downloads all dependencies again.

**Side effects:** Locally installed artifacts are removed; builds re-download dependencies.

**Folders:**

- `%USERPROFILE%\.m2\repository`

### npm cache

`clean.dev.npm` | Advanced | Tier A | method files | reversible: none

*Clears the npm package cache. Packages download again on the next install. Close Node tools first.*

Deletes the npm cache folder (%LOCALAPPDATA%\npm-cache), the same data 'npm cache clean --force' removes. Installed node_modules folders are not touched. The next installs download packages again.

**Side effects:** The next npm installs are slower and need network access.

**Folders:**

- `%LOCALAPPDATA%\npm-cache\_cacache`
- `%LOCALAPPDATA%\npm-cache\_logs`

**Sources:** <https://docs.npmjs.com/cli/v10/commands/npm-cache>

### NuGet HTTP cache and scratch

`clean.dev.nuget` | Advanced | Tier A | method files | reversible: none

*Clears NuGet's HTTP cache and temp scratch folders. The global packages folder is kept.*

Deletes the NuGet v3 HTTP cache and the NuGetScratch temp folder, like 'dotnet nuget locals http-cache --clear'. The global packages folder (~\.nuget\packages) is not touched, so builds keep working offline.

**Side effects:** Package metadata is downloaded again on the next restore.

**Folders:**

- `%LOCALAPPDATA%\NuGet\v3-cache`
- `%LOCALAPPDATA%\NuGet\http-cache`
- `%TEMP%\NuGetScratch`

**Sources:** <https://learn.microsoft.com/en-us/nuget/consume-packages/managing-the-global-packages-and-cache-folders>

### pip cache

`clean.dev.pip` | Advanced | Tier A | method files | reversible: none

*Clears the pip download and wheel cache. Packages download again on the next install.*

Deletes the pip cache (%LOCALAPPDATA%\pip\Cache), the same data 'pip cache purge' removes. Installed packages and virtual environments are not touched.

**Side effects:** The next pip installs are slower and need network access.

**Folders:**

- `%LOCALAPPDATA%\pip\Cache`

**Sources:** <https://pip.pypa.io/en/stable/topics/caching/>

### VS Code caches and logs

`clean.dev.vscode` | Advanced | Tier B | method files | reversible: none

*Clears VS Code's cached data, downloaded extension installers and logs. VS Code must be closed.*

Deletes VS Code's CachedData, CachedExtensionVSIXs, web cache and log folders. Installed extensions, settings and workspaces are not touched. VS Code must be closed.

**Side effects:** VS Code starts a little slower once.

**Folders:**

- `%APPDATA%\Code\CachedData`
- `%APPDATA%\Code\CachedExtensionVSIXs`
- `%APPDATA%\Code\Cache`
- `%APPDATA%\Code\Code Cache`
- `%APPDATA%\Code\GPUCache`
- `%APPDATA%\Code\logs`

### Yarn cache

`clean.dev.yarn` | Advanced | Tier B | method files | reversible: none

Deletes the Yarn classic cache under %LOCALAPPDATA%\Yarn\Cache, the same data 'yarn cache clean' removes. Project folders are not touched.

**Folders:**

- `%LOCALAPPDATA%\Yarn\Cache`

### Old files in Downloads (to Recycle Bin)

`clean.downloads.old` | Advanced | Tier B | method files | reversible: partial

*Moves files untouched for 60+ days from Downloads to the Recycle Bin. Opt-in; review the list before cleaning.*

Moves files in your Downloads folder that were not created or changed for at least 60 days to the Recycle Bin, so you can still restore them. This rule is never selected automatically. Review the sample list after scanning, because Downloads often holds files people mean to keep.

**Side effects:** Files go to the Recycle Bin; emptying it later deletes them permanently.

**Folders:**

- `%USERPROFILE%\Downloads`

**Filters:** older than 1440 h; to the Recycle Bin.
