# ASR Center and security score

> Generated by `tools\Build-Docs.ps1` from `data\asr\rules.json` and `src\Security\SecurityScore.ps1`. Do not edit by hand.

Microsoft Defender attack surface reduction (ASR) rules block behaviors malware relies on. The ASR Center (GUI page, `-Asr`, `-AsrAudit`) shows every rule with its mode, what it means for games, launchers and mods, and the exclusions that apply to it. Modes iG Windows Tuner can set: Not configured (Windows default), Audit, Warn (where supported) and Block. It never writes an explicit Off and never changes server-only rules or rules managed by Group Policy or MDM. Every change writes a snapshot first and can be reverted from Backups & Logs or with `-RevertAll -Snapshot <file>`.

Recommended modes for a gaming PC: the three standard protection rules and the rules without gamer impact in Block; rules that can catch games, launchers or mods in Audit, so you can review the audit view first. `-AsrRecommended` only ever raises a rule.

## Rules

### Block abuse of exploited vulnerable signed drivers

`56a863a9-875e-4185-98a7-b882c64b5ce5` | key `vulnerable-drivers`

Prevents applications from writing vulnerable signed drivers (drivers with known flaws that malware and some cheats load to get kernel access) to disk. Drivers that are already installed are not affected; the Microsoft vulnerable driver blocklist covers loading. Microsoft lists it as a standard protection rule that can go straight to Block.

- **Gamer impact (low):** None for games or anti-cheat. Old RGB, fan-control or overclocking tools that ship a known-vulnerable driver may fail to install it.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-abuse-of-exploited-vulnerable-signed-drivers>

### Block credential stealing from the Windows local security authority subsystem

`9e6c4e1f-7d60-472f-ba1a-a39ef669e4b2` | key `lsass`

Blocks processes from opening the Local Security Authority (LSASS) process with memory-read access, the technique credential dumpers use. When LSA protection is on, the rule adds no extra protection but does no harm. Expect block events for svchost.exe, updaters and monitoring tools: they are only denied access to LSASS memory, not stopped from running. Warn mode is not supported.

- **Gamer impact (none):** None. Block events for Windows services and launcher updaters are expected noise that Microsoft says can be ignored; nothing stops working.
- **Notes:** Redundant when LSA protection (sec.lsa-protection) is on. Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-credential-stealing-from-the-windows-local-security-authority-subsystem>

### Block persistence through WMI event subscription

`e6db77e5-3df2-4cf1-b95a-636979351e5b` | key `wmi-persistence`

Blocks the creation of permanent WMI event subscriptions, a fileless persistence technique where malware keeps its trigger in the WMI repository instead of on disk. Microsoft lists it as a standard protection rule; the only known conflict is the Configuration Manager client, which home PCs do not use.

- **Gamer impact (none):** None for games. Only tools that create permanent WMI event subscriptions are affected, which consumer software rarely does.
- **Notes:** Test in Audit first on PCs managed by Configuration Manager. Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-persistence-through-wmi-event-subscription>

### Block executable content from email client and webmail

`be9ba2d9-53ea-4cdc-84e5-9b1eeee46550` | key `email-executable`

Stops executable files (exe, dll, scr), scripts (ps1, vbs, js) and archives opened from Outlook, Outlook.com and other popular webmail services from running. Malicious attachments are still one of the most common ways malware arrives. iG Windows Tuner's gaming-safe baseline (sec.asr-baseline) already sets it to Block.

- **Gamer impact (none):** None for games. Executable attachments opened from mail are blocked; save them through a browser download if you trust the sender.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-executable-content-from-email-client-and-webmail>

### Block JavaScript or VBScript from launching downloaded executable content

`d3e037e1-3eb8-44c8-a917-57927947596d` | key `script-downloads`

Malware written in JavaScript or VBScript often only downloads and starts the real payload. This rule blocks scripts from launching executables they fetched from the internet. A few old installers use such a script stub, but games and launchers do not. iG Windows Tuner's gaming-safe baseline already sets it to Block.

- **Gamer impact (none):** None for games. Old installers that use a VBScript or JScript stub to download and start an exe may fail.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-javascript-or-vbscript-from-launching-downloaded-executable-content>

### Block execution of potentially obfuscated scripts

`5beb7efe-fd9a-4556-801d-275e5ffc04cc` | key `obfuscated-scripts`

Detects suspicious properties of obfuscated scripts, which malware uses to hide what it does. It covers PowerShell and relies on AMSI and cloud-delivered protection, so it only works fully with cloud protection on. iG Windows Tuner's gaming-safe baseline already sets it to Block.

- **Gamer impact (low):** Low. A few mod installers or tweak scripts that pack their code can be blocked; games and launchers themselves are not affected.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-execution-of-potentially-obfuscated-scripts>

### Block untrusted and unsigned processes that run from USB

`b2b3f03d-6a65-4f7b-a9c7-1c7ef74a9ba4` | key `usb-untrusted`

Prevents unsigned or untrusted executable files from running from removable drives, including SD cards. Copying files from the drive still works; files copied to the disk are judged where they run. iG Windows Tuner's gaming-safe baseline already sets it to Block.

- **Gamer impact (low):** Low. Unsigned portable tools started straight from a USB stick are blocked; signed programs and copying files are not affected.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-untrusted-and-unsigned-processes-that-run-from-usb>

### Block rebooting machine in Safe Mode

`33ddedf1-c6e0-47cb-833e-de6133960387` | key `safe-mode-reboot`

Ransomware sometimes restarts Windows in Safe Mode, where many security products do not run, before encrypting files. This rule blocks commonly abused commands such as bcdedit and bootcfg from setting a Safe Mode boot. You can still reach Safe Mode through the Windows Recovery Environment (Settings > System > Recovery > Advanced startup).

- **Gamer impact (none):** None for games. Troubleshooting guides that set Safe Mode with bcdedit will not work; use Advanced startup instead.
- **Notes:** Microsoft lists it under the rules to test in Audit first.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-rebooting-machine-in-safe-mode>

### Block use of copied or impersonated system tools

`c0033c00-d16d-4114-a5a0-dc9b3a7d2ceb` | key `copied-system-tools`

Treats the programs in System32 and SysWOW64 as Windows system tools and blocks copies or same-named files that run from other locations, even when signed. Microsoft notes that its heuristics can also flag legitimate third-party programs that run from non-default install paths. Audit first and add a per-rule exclusion for any trusted program it reports.

- **Gamer impact (medium):** Medium. Games, launchers or tools installed in custom folders can match the heuristics; check the audit view before switching to Block.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-use-of-copied-or-impersonated-system-tools>

### Block executable files from running unless they meet a prevalence, age, or trusted list criterion

`01443614-cd74-433a-b99e-2ecdc07bfc25` | key `prevalence-age`

Blocks executable files that are not yet prevalent, old enough or on a trusted list, judged by cloud-delivered protection. Brand-new malware is caught this way, but so is any legitimate program that few people have run yet. Cloud protection must be on. Use Audit or Warn and review the audit view before considering Block.

- **Gamer impact (high):** High. Freshly patched games, indie and beta builds, mod managers and community tools can be blocked until their reputation builds up.
- **Notes:** Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-executable-files-from-running-unless-they-meet-a-prevalence-age-or-trusted-list-criterion>

### Use advanced protection against ransomware

`c1db55ab-c21a-4637-bb3f-a12568109d35` | key `ransomware`

Uses client and cloud heuristics to decide whether a file resembles ransomware. Signed files, files the cloud knows to be clean and prevalent files are not blocked, but unknown files without a positive reputation can be. Such blocks usually clear as reputation grows. Cloud protection must be on.

- **Gamer impact (medium):** Medium. Unsigned, little-known executables such as new indie games, mods or trainers can be blocked until they gain reputation. Audit first.
- **Notes:** Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#use-advanced-protection-against-ransomware>

### Block process creations originating from PSExec and WMI commands

`d1e49aac-8f56-4280-b9ba-993a6d77406c` | key `psexec-wmi`

PsExec and WMI can start programs remotely, and malware uses them for command and control or to spread across a network. This rule blocks every process created that way. Some legitimate software, including updaters, hardware utilities and management scripts, also starts processes through WMI, so test it in Audit first.

- **Gamer impact (medium):** Medium. Launchers, updaters or hardware utilities that start helpers through WMI can break. Check the audit view before using Block.
- **Notes:** Never enable on PCs managed by Configuration Manager. Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-process-creations-originating-from-psexec-and-wmi-commands>

### Block all Office applications from creating child processes

`d4f940ab-401b-4efc-aadc-ad5f3c50688a` | key `office-child-processes`

Malicious documents usually run macros or exploit code that starts PowerShell, cmd or a downloaded payload. This rule blocks Office apps from creating child processes. Some add-ins and business macros do this legitimately, so audit first. It is only enforced when Office is installed under Program Files.

- **Gamer impact (none):** None for games. Office add-ins or macros that start Command Prompt, PowerShell or helper apps are blocked.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-all-office-applications-from-creating-child-processes>

### Block Office applications from creating executable content

`3b576869-a4ec-4529-8536-b80a7769e899` | key `office-executable-content`

Prevents Word, Excel and PowerPoint from saving malicious components to disk where they survive a restart, and blocks running untrusted files that macros wrote. It does not depend on where Office is installed. Audit first if you rely on macros that generate files.

- **Gamer impact (none):** None for games. Only Office documents and macros that save and run executable files are affected.
- **Notes:** Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-office-applications-from-creating-executable-content>

### Block Office applications from injecting code into other processes

`75668c1f-73b5-4cf0-bb93-3ecf5cb7cc84` | key `office-injection`

Attackers inject code from Office into other processes so it runs disguised as a clean program. Microsoft knows of no legitimate business purpose for this. The rule applies to Word, Excel, OneNote and PowerPoint installed under Program Files, needs an Office restart to take effect and does not support Warn mode.

- **Gamer impact (none):** None for games. A few security products (BeyondTrust Privilege Guard, Heimdal) are listed by Microsoft as incompatible.
- **Notes:** Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-office-applications-from-injecting-code-into-other-processes>

### Block Office communication application from creating child processes

`26190899-1602-49e8-8b27-eb1d0a1ce869` | key `outlook-child-processes`

Prevents Outlook from creating child processes, which blocks social-engineering payloads and the Outlook rules and forms exploits attackers use with stolen credentials. Normal mail features keep working. It is only enforced when Office is installed under Program Files.

- **Gamer impact (none):** None for games. Outlook add-ins that start external programs are blocked.
- **Notes:** Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-office-communication-application-from-creating-child-processes>

### Block Win32 API calls from Office macros

`92e97fa1-2edf-4476-bdd6-9dd0b4dddc7b` | key `office-macro-win32`

Office VBA can call Win32 APIs, which malware abuses to launch shellcode without writing files. The rule blocks those calls from macros. Most people who use macros at all never need Win32 API calls, but audit first if you run complex business macros.

- **Gamer impact (none):** None for games. Only Office macros that call Windows APIs are affected.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-win32-api-calls-from-office-macros>

### Block Adobe Reader from creating child processes

`7674ba52-37eb-4a4f-a9a1-f0f9a1619a2c` | key `adobe-child-processes`

Malicious PDFs use social engineering or exploits to make Adobe Reader download and start a payload. Blocking Reader from creating child processes stops that path. Reader plug-ins or workflows that open other programs can be affected, so audit first if you depend on them.

- **Gamer impact (none):** None for games. Only Adobe Reader workflows that start other programs are affected.
- **Notes:** Limited exclusion support.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-adobe-reader-from-creating-child-processes>

### Block Webshell creation for Servers

`a8f5898e-1dc8-49a9-9878-85004b8a61e6` | key `webshell-servers`

Blocks web shell scripts on Windows servers that run Microsoft Exchange. It does not apply to Windows 11 clients, and Microsoft advises leaving it Not configured outside Defender for Endpoint management to avoid conflicts. iG Windows Tuner shows it for completeness and does not change it.

- **Gamer impact (none):** None. The rule only applies to Exchange servers.
- **Source:** <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference#block-webshell-creation-for-servers>

## Exclusions

- **Per-rule exclusions** (recommended) are written to the documented Group Policy registry settings: `HKLM\SOFTWARE\Policies\Microsoft\Windows Defender\Windows Defender Exploit Guard\ASR\ASROnlyPerRuleExclusions` (value name = rule GUID, data = paths separated by `>`) plus the policy switch `ExploitGuard_ASR_ASROnlyPerRuleExclusions = 1`. When iG Windows Tuner runs as administrator it confirms through `Get-MpPreference` that Defender picked them up.
- **Global ASR exclusions** use `Add-MpPreference -AttackSurfaceReductionOnlyExclusions` and apply to every rule.
- Refused: drive roots, the Windows folder, the whole Program Files folders, folders or wildcards inside user profiles and ProgramData, Downloads, Desktop, browser cache and temp folders, user environment variables, relative segments, quotes and the `>` separator. Folder exclusions must be at least two levels deep. Exclude the program file itself whenever possible.
- Defender applies exclusions when a program starts; restart the program after adding one. Antivirus scan exclusions are never added.

## Audit view

`-AsrAudit [-Days N]` and the GUI read the Defender Operational log (read-only): ASR 1121 (block), 1122 (audit), 1129 (Warn bypass); controlled folder access 1123/1127 (block), 1124/1128 (audit); network protection 1125 (audit), 1126 (block); 5007 (configuration change). Events are grouped by rule and program, with a next step: promote a quiet Audit rule (after at least 7 days of log coverage), add a per-rule exclusion for a trusted program's exact file, or ignore expected LSASS noise from Windows components.

## Security score

`-SecurityScore`, `-Report` and the dashboard. Pass earns the weight, Warn half, Fail nothing; not applicable, managed and unreadable checks are left out. Grades: Strong 90+, Good 75+, Fair 50+, Weak below.
