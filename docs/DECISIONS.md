# Decisions and deviations

Every design choice that departs from common tuning advice, or where several options existed, is recorded here with its reason and source. The rule applied throughout: **when in doubt, keep the Windows default; when documentation and the seed catalog disagree, follow the documentation.**

## Tweak catalog corrections

| # | Topic | Common advice | Decision | Source |
|---|---|---|---|---|
| D1 | MMCSS "Games" task profile (GPU Priority 8, Priority 6, Scheduling Category High, SFIO High) | Tier B, Competitive | **Rejected** (documented in `rejected.json`). Microsoft documents *GPU Priority* as "not yet used", *SFIO Priority* as "not used", and says *Priority* is "always treated as 2" when Scheduling Category is High. Only threads that register with the MMCSS "Games" task are affected at all. The only remaining effect would be Scheduling Category High (priority 23-26, meant for pro audio), which can starve system threads. | <https://learn.microsoft.com/en-us/windows/win32/procthread/multimedia-class-scheduler-service> |
| D2 | MMCSS SystemResponsiveness | 10; "verify handling of values < 10" | Kept at **10**. Microsoft: values not divisible by 10 are rounded down, and values below 10 or above 100 are clamped to 20. So 0 (a common recommendation) behaves like the default 20, and 10 is the lowest effective value. | same |
| D3 | "No auto-restart while signed in" (`NoAutoRebootWithLoggedOnUsers`) | Tier A, all presets | **Replaced** by the documented active-hours policy (`SetActiveHours=1`, 10:00-04:00, the 18 h maximum). Added to the Rejected list. | <https://learn.microsoft.com/en-us/windows/deployment/update/waas-restart> |
| D4 | "Nagle off" (`TcpAckFrequency=1`, `TCPNoDelay=1`) | Tier B, manual | Implemented as **"TCP delayed ACK off"** with `TcpAckFrequency` only (documented in KB 328890). `TCPNoDelay` as an interface registry value is not read by the Windows TCP stack (Nagle is the per-socket `TCP_NODELAY` option), so it is rejected. Its measured gain over High performance is small. A copy that already exists is reused, and revert deletes only a copy that iG Windows Tuner created. | <https://learn.microsoft.com/en-us/windows-hardware/design/device-experiences/powercfg-command-line-options> |
| D9 | NIC "allow the computer to turn off this device" | Tier A, presets C, B, H | **Tier B, Competitive only.** The only Microsoft documentation (KB 2740020, `PnPCapabilities=24`) was written for Windows 7 and has been retired (both the English and localized URLs now redirect to a generic power-management page). ## Engine and platform

| # | Decision | Reason |
|---|---|---|
| E1 | Restore points are created through the WMI class `root\default:SystemRestore` instead of `Checkpoint-Computer`. | `Checkpoint-Computer` does not exist in PowerShell 7; WMI works in both 5.1 and 7. |
| E2 | Binary registry data in snapshots is stored as **hex text**, not Base64. | Keeps the shipped code free of Base64 APIs (one of the Defender-friendliness rules) and makes snapshots human-readable. |
| E3 | Adapter advanced properties are written with `-NoRestart` (requires: reboot). | Never drop the network link mid-apply, especially over Remote Desktop. |
| E4 | Kernel DMA protection is detected with `Win32_DeviceGuard.AvailableSecurityProperties` value 3. | Querying the Kernel DMA Protection flag directly needs an undocumented native call, which would add a second P/Invoke. msinfo32 confirms it. |
| E5 | Non-elevated TPM detection uses the "Trusted Platform Module 2.0" PnP device; full readiness (`Get-Tpm`) needs elevation. | `Get-Tpm` and `Win32_Tpm` require administrator rights, and `-Report` must run read-only without elevation. |
| E6 | The CPU microcode is parsed from the 4-byte `Update Revision` format (26300 stores `2F 01 00 00` = 0x12F); the older 8-byte format (revision in the high DWORD) is also handled. | Observed on build 26300; both formats are covered by unit tests. |
| E7 | **Per-monitor DPI.** WPF hosted by `powershell.exe` is system-DPI aware and renders vector UI crisply at 100/125/150 % on the primary display. Per-monitor-V2 awareness would need an application manifest or a second P/Invoke (`SetProcessDpiAwarenessContext`), which conflicts with the "one P/Invoke" rule. Layouts were verified by rendering every page at 1.0/1.25/1.5 scale (`Show-IgwtGui -RenderTo -Scale`). | Project scope. |
| E8 | Turning a toggle **off** in the GUI reverts from the newest iG Windows Tuner snapshot if one exists; otherwise it resets to the documented Windows default. The preview says which will happen. | "Off" must restore the user's previous value, not an arbitrary one. |
| E9 | Startup Apps toggles apply immediately, with a snapshot (like Task Manager), and require elevation. | They are single, fully reversible StartupApproved values, and a snapshot is always written. Requiring admin keeps all backups in the admin-only folder. |
| E10 | A short-lived read cache (5-10 s) is used for slow queries such as `Get-MpPreference` and `powercfg /list`. It is cleared at the start of every operation and after every write, and disabled in TestMode. | A full state scan went from about 10 s to about 3 s without risking stale state. |
| E11 | Pester **5.7.1** is the documented test runner (5.x API). Pester 6.2.0 was also installed by `Install-Module -MinimumVersion 5.5.0`, but `tools\Invoke-QualityChecks.ps1` pins 5.x. | Section 14 asks for Pester 5. |
| E12 | Three PSScriptAnalyzer rules are excluded in `PSScriptAnalyzerSettings.psd1`, with justification: `PSReviewUnusedParameter` (uniform action signature), `PSUseSingularNouns` (collection getters) and `PSUseOutputTypeCorrectly` (informational). UI-only `Update-*`/`New-*` functions carry targeted `SuppressMessage` attributes. | Section 14: "warnings fixed or justified". |
| E13 | FACEIT's support pages return HTTP 403 to automated fetches. Their content was verified through search results and press coverage; the Riot page was fetched directly. | See `docs\ANTICHEAT.md`. |

## Schema v2 and migration (2.0)

| # | Decision | Reason |
|---|---|---|
| S1 | **The tweak tier stays in `evidence.tier`**; cleaner rules carry a top-level `tier`. Loaded tweaks get a computed `tier` property, so every item kind exposes it the same way. | Items list "level, tier" as fields; for tweaks the tier belongs next to the sources that justify it, and duplicating it could drift. |
| S2 | **v1 levels are derived, not guessed by hand:** expert + not anti-cheat safe = Lab, other expert = Expert, Tier B or medium/high risk = Advanced, otherwise Standard. Result: 42 Standard, 23 Advanced, 2 Expert, 1 Lab. | Deterministic and reviewable; Lab means ("knowingly breaks anti-cheat or a security feature"), which describes the VBS/HVCI-off toggle. |
| S3 | **`antiCheat` is derived from `antiCheatSafe` plus the warning text** (known names: FACEIT, Riot Vanguard, Easy Anti-Cheat, BattlEye, RICOCHET, Javelin); with no name found it would be `"unknown"`. | Keeps the documented anti-cheat impact exact instead of a generic "breaks". |
| S4 | **v1 `appliesTo.hardware` became `appliesTo.conditions`**, and the new `hardware.tags` start empty. | The v1 values (wired adapter present, Defender active, not RDP, multiple GPUs) are runtime conditions, not hardware tags. Real tags come from the hardware profile engine; the tag vocabulary (`data\hardware\tags.json`) is defined now so validation can reject unknown tags. |
| S5 | **v1 snapshots are never rewritten.** They are upgraded in memory on read (and listed normally); the tool only writes schema 2 copies to a different folder. `data\migration\id-map.json` (empty in 2.0) handles future id renames. | Backups are the user's safety net; changing them in place could break the only way back. A real 1.0 snapshot is a test fixture and is reverted by the suite. |
| S6 | **v1 presets became intent presets** (`include`, `exclude`, `levelCeiling: Advanced`, `antiCheatPolicy: safeOnly`, `gaming: true`); the in-memory `tweaks` list is `include` minus `exclude`. Preset hints were written by hand after the migration. | The engine, CLI and GUI keep using one resolved member list, which the hardware overlays extend. |
| S7 | **Data files are written with `ConvertTo-IgwtJson`**, not `ConvertTo-Json`. | Windows PowerShell 5.1 escapes `<`, `>` and `'` (so `<absent>` becomes `<absent>`), has a depth limit and produces irregular indentation. The custom writer is ASCII-only and round-trips every data file (tested). |
| S8 | **Expert and Lab gates are unchanged for now:** both need `-AcknowledgeRisk` or the GUI confirmation, as in 1.0. The one-time acknowledgement, mandatory restore point, typed confirmation and red banner are planned for the GUI mode switch. | The gates belong in the GUI restructure; changing them twice would be churn. |
| S10 | **Cleaner rule tier:** A when the rule cites a vendor source, B for well-known cache locations without one. | Same meaning as the tweak tiers: documented vs. situational. |

## Action handlers (2.0)

| # | Decision | Reason |
|---|---|---|
| A1 | **No `bcd` handler.** BCD stays read-only; there are no BCD writes, not even for Lab items. | The v1 invariant and the project's scope notes; `tests\Safety.Tests.ps1` keeps enforcing it. This is deliberate. |
| A2 | **No `fileAssociation` writer.** Windows protects per-user default apps with the UserChoice hash, and the only programmatic method (the DefaultAssociationsConfiguration policy) applies to domain-joined PCs only. A read-only `check` (`checker: DefaultApp`) shows the current default app and points to Settings > Apps > Default apps. | <https://learn.microsoft.com/en-us/windows/client-management/mdm/policy-csp-applicationdefaults>; writing hash-protected values would be a bypass. |
| A3 | **ASR exclusions live in the ASR Center.** The existing `asrRule` handler keeps its modes. Resolved in R3/R4. | Exclusions weaken a rule for specific paths and belong next to the per-rule gamer-impact notes and audit data. |
| A4 | **Registry-backed types are composites** (`storageSense`, `wufbPolicy`, `deviceInterrupt`, `serviceSet`): they expand into the existing registry/service parts and reuse their snapshot and restore code; the expansion always comes from the catalog (and the devices present now), never from the snapshot file. | One proven primitive for exact types, absent values and created keys. |
| A5 | **`deviceInterrupt`** only targets present PCI Display, Net and USB host controllers, sets MSI values only where the driver declares MSI support, refuses USB host controllers when Windows boots from USB, needs `requires: reboot` and level Expert or Lab, and has no "reset to default" (the driver INF sets the defaults; revert uses the snapshot). | <https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/enabling-message-signaled-interrupts-in-the-registry>, <https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/interrupt-affinity-and-priority>; never the boot-disk controller. |
| A6 | **`firewallRule`** only reduces exposure: iG Windows Tuner creates Block rules named `iGWindowsTuner-*` in its own group, or disables an existing rule group; it never creates Allow rules. **`scheduledTask`** only enables or disables existing tasks and refuses Defender, Windows Update, WaaSMedic, TPM, BitLocker, restore, time and AppID tasks. | No persistence and no security reduction (project rules). |
| A7 | **`exploitSystem` can only turn mitigations ON**; `processMitigation` OFF needs level Expert or Lab. Values are captured as ON/OFF/NOTSET; NOTSET is restored with `Set-ProcessMitigation -Remove -Disable <name>`. | <https://learn.microsoft.com/en-us/powershell/module/processmitigations/set-processmitigation> (example 4: `-Remove` restores the default). |
| A8 | **`appx` removal is `reversible: partial`**: revert re-registers the app from its install folder, else reinstalls it from the Store through winget (`storeId`); a removed provisioned copy is not restored for new profiles. Store, App Installer, Windows Security, shell, Xbox identity, Gaming Services and frameworks are protected. | Honest reversibility labels (schema v2). |
| A9 | **`winget`** runs only through `Invoke-IgwtWinget` with fixed arguments (`--exact`, `--silent`, `--accept-package-agreements`, `--accept-source-agreements`, `--disable-interactivity`); it refuses to run in TestMode. | Network use only for user-initiated winget operations. |
| A10 | **`wufbPolicy`** limits: feature updates 0-365 days, quality updates 0-30 days, target release `Windows 11` + `NNH1/NNH2`. No "disable all"; pausing stays in Settings. Microsoft's pages list 0-30 or 0-35 for quality deferral; 30 is used. | <https://learn.microsoft.com/en-us/windows/deployment/update/waas-configure-wufb> |
| A11 | **The Storage Sense tweaks now use the typed `storageSense` action.** They are new in 2.0, so no released snapshot depends on their old fingerprints; 1.0 tweaks keep their actions unchanged. | Readable catalog entries with range validation. |

## Hardware profile engine (2.0)

| # | Decision | Reason |
|---|---|---|
| H1 | **Blocks are enforced in state detection**, not only in presets: a blocked item is Not applicable, so neither a preset nor `-Apply` can turn it on. An item that was applied before the overlay existed keeps its real state (On) with a "turning it off is recommended" reason, so it can still be reverted or reset. | A block is a hardware-safety rule (for example idle-disable on Raptor Lake); it must hold everywhere, but it must never trap a user with a setting they cannot undo. |
| H2 | **Your add-ons cannot bypass a block**; your removals and the preset's `exclude` always win over overlay adds. Overlay adds also respect the preset's level ceiling and anti-cheat policy, and never add Lab items. | Project scope. plus the preset safety rules from section 10. |
| H3 | **AMD X3D dual-CCD rule cites reviewer guidance.** AMD's chipset driver release notes document the 3D V-Cache Performance Optimizer, but no public AMD support page states the Balanced-plan / Game Bar requirement; reviewers (Notebookcheck) report it as AMD's recommendation, and forum results on other plans vary. The overlay is marked `basis: reviewer`. | the evidence is recorded honestly instead of overstated. |
| H4 | **SysMain rule is an iG Windows Tuner policy** (`basis: igwt`): no Microsoft page quantifies SysMain's benefit on hard disks or with little RAM, so the rule keeps the Windows default there. Memory compression has no catalog item to block yet. | Conservative default where documentation is missing. |
| H5 | **VM detection uses manufacturer/model strings, never `HypervisorPresent`**, which is also true on any PC where VBS runs Windows on the hypervisor. CPU-derived tags (`intel.hybrid`, `intel.raptorlake.desktop`) are not set inside a VM, where virtual processors look like cores without Hyper-Threading. | Avoids marking every VBS-enabled gaming PC as a VM. |
| H6 | **The VM overlay blocks adapter driver properties and power management (netAdapterAdvanced, netAdapterPower), USB/PCIe power and Wi-Fi**, but not per-interface TCP/IP settings (NetBIOS, delayed ACK). | Those registry settings exist on virtual adapters too; blocking them would hide valid security settings in Windows Sandbox runs. |
| H7 | **`intel.raptorlake.desktop` excludes mobile suffixes (H, HX, P, U)** even though HX parts share the Raptor Lake-S model number. | Intel's Vmin Shift statements concern 13th/14th gen desktop processors. The microcode health check is unchanged. |
| H8 | **Laptop rule blocks plan switches only.** iG Windows Tuner's power items write AC values exclusively, so DC battery saving is already never reduced; a matcher blocks any future item that writes DC values. The I226 overlay adds the EEE-off item, Intel's documented mitigation for random disconnects. | The I226 source is an official Intel communication on Intel's community site. |
| H9 | **Hardware tags in item `hardware.tags`/`excludeTags` stay empty in the shipped catalog**; overlays carry the hardware logic. | Keeps each rule in one place with its source; item-level tags remain available for future hardware-specific items. |

## Cleaning engine (2.0)

| # | Decision | Reason |
|---|---|---|
| C1 | **Allow-list rules plus a denylist in the deletion primitive.** Rules (`data\cleaner\*.json`) name the folders they may clean, and `Remove-IgwtCleanerFile` enforces the protections in code for every file: drive, Windows, Program Files, ProgramData, profile and user-document roots, Defender, OneDrive and Downloads. | A wrong or edited rule file must never be able to delete something important. The rule files are data; the guarantees live in the primitive and are covered by tests. |
| C2 | **Scan, then clean only the scanned set.** Each file is re-validated right before deletion: canonical path, root membership (roots re-resolved at clean time), denylist, parent reparse points, unchanged size and write time, minimum age. | Closes the time-of-check/time-of-use gap (for example a folder swapped for a junction after the scan) and keeps "what you saw is what gets deleted". |
| C3 | **No recursive deletes.** Only single files and empty folders are removed. | A recursive delete that meets a junction or a mis-resolved root is the classic cleaner disaster. |
| C4 | **`cleanmgr` is not used.** Its handlers are COM objects driven by `/sageset` registry state, are partly deprecated on Windows 11, and their deletions are not observable per file. | Every deletion must be logged and testable. |
| C5 | **Windows.old and upgrade leftovers are guidance only.** The rule shows the size and points to Settings > System > Storage > Temporary files. | Removing them needs ownership and ACL changes (the cleaner never takes ownership) and is Windows' own rollback mechanism. |
| C6 | **Component store and driver store use the supported tools.** `Repair-WindowsImage -StartComponentCleanup` (ResetBase only in the Expert rule), and `pnputil /delete-driver` **without `/force`** for packages that have a newer version and are not bound to a present device. | iG Windows Tuner never deletes inside WinSxS or the DriverStore directly; Windows refuses anything still in use. |
| C7 | **Browser rules clean caches only.** Cookies, history, passwords and session data are never deleted (a privacy wipe is deferred). Opera's profile lives in Roaming AppData, which is protected; only its Local AppData cache is cleaned. | Signing users out of everything is not "junk cleaning". |
| C8 | **Steam exceptions are in code**, not in rule files: `Steam\steamapps\shadercache`, `Steam\logs`, `Steam\dumps` and `Steam\appcache\httpcache` under Program Files are the only allowed paths inside Program Files. | Keeps Program Files protected even if a rule file is changed. |
| C9 | **Apps are never closed.** Rules list the processes that must not run (`requiresClosed`); while one runs, the rule reports "Close the app first" and is skipped. | Killing a game launcher or browser can lose user data. |
| C10 | **Below-normal thread priority, no I/O priority.** Setting the I/O priority would need a P/Invoke (`SetThreadInformation`), which conflicts with the "one P/Invoke" rule. | Same rule as E7. |
| C11 | **Spotify rule not shipped.** Its cache and offline-download folders overlap and differ by app version (desktop vs Store). | Users would lose downloaded songs; Spotify's own Settings > Storage > Clear cache is the safe path. |
| C12 | **The opt-in Downloads rule moves files to the Recycle Bin** and only touches files not created or changed for 60 days. | Downloads often holds files people meant to keep. |
| C13 | **The non-elevated GUI can clean user-level rules** (temp, caches) after a confirmation; admin rules show "Needs administrator". The CLI elevates only when a selected rule needs it. | Per-user caches belong to the signed-in user; elevating with a different admin account would clean the wrong profile. |
| C14 | **Storage Sense uses the documented Policy CSP values** under `HKLM\SOFTWARE\Policies\Microsoft\Windows\StorageSense` (absent by default). The Downloads threshold is an expert toggle outside every preset. While a policy is set, the Settings page shows "managed by your organization". | Policies are the only documented, revertible way to configure Storage Sense; per-user `StorageSense\Parameters` values are undocumented. |

## ASR Center and security modules (2.0)

| # | Decision | Reason |
|---|---|---|
| R1 | **All 19 ASR rules live in `data\asr\rules.json`** with hint, description, gamer-impact note and level, Warn support, cloud dependency, server-only flag, recommended mode and sources. GUIDs, Warn limits (LSASS and Office injection do not support Warn), cloud dependencies and the Exchange-only webshell rule were checked against the Microsoft Learn reference (updated 9 Sep 2026). `Test-IgwtCatalog` validates the file and every `asrRule` action of the tweak catalog against it. | <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-reference> |

Server-only rules and rules set by Group Policy or MDM are shown but never changed (local settings would be overwritten at startup). A previously captured Off is still restored exactly on revert. | <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-overview> (modes table); <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-configure> (policy precedence) |
| R3 | **Per-rule exclusions use the Group Policy registry settings**: `...\Windows Defender Exploit Guard\ASR\ASROnlyPerRuleExclusions` (value name = rule GUID, REG_SZ `path>path`) plus `ExploitGuard_ASR_ASROnlyPerRuleExclusions = 1`, as defined in the inbox `WindowsDefender.admx`. Microsoft documents per-rule exclusions only for Group Policy "and the corresponding registry settings", Intune and the Defender portal. The local `Add-MpPreference -AttackSurfaceReductionRules_RuleSpecificExclusions*` parameters exist but are undocumented, so they are only read (as administrator) to confirm Defender picked the values up. | <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-rules-overview#file-and-folder-exclusions-for-asr-rules>; ADMX policy `ExploitGuard_ASR_ASROnlyPerRuleExclusions`. |
| R4 | **Exclusions are validated before anything changes.** Refused: drive roots, the Windows folder, the whole Program Files folders, folders or wildcards in user profiles and ProgramData, Downloads/Desktop/temp/browser-cache folders, user environment variables (Microsoft supports only system variables), relative segments, quotes and `>`. Folder exclusions must be two levels deep; a wildcard may stand for one folder below a named folder only. Antivirus exclusions (`ExclusionPath` and friends) are never added; a static test enforces it. | Microsoft: excluded files run without reports, and exclusions should be as narrow as possible. |
| R5 | **Every ASR Center change writes an `ASR` snapshot first**; revert goes through `Invoke-IgwtRevert` (Backups & Logs, `-RevertAll -Snapshot`). Rule GUIDs are re-validated against the catalog and registry paths come from code, never from the file. A revert writes its own snapshot so it can be undone. | Same reversibility rule as every tweak. |
| R6 | **Recommendations for a gaming PC:** the three standard protection rules and rules without gamer impact (email, scripts, obfuscation, USB) in Block, which matches the 1.0 `sec.asr-baseline`; rules that can catch games, launchers or mods (prevalence/age, ransomware heuristics, copied system tools, PsExec/WMI) and the Office/Adobe rules in Audit; Safe Mode reboot in Audit because Microsoft lists it among the rules to test first. "Apply recommendations" never lowers a rule. Validation refuses Block as the recommendation for medium or high gamer impact. | Microsoft's guidance: standard rules straight to Block, other rules audited first. |
| R7 | **Audit view recommendations:** promote a quiet Audit rule only after at least 7 days of Defender log coverage (Warn first for medium/high gamer impact); suggest a per-rule exclusion only for the exact file, only when it passes R4, never for Windows paths; LSASS events are expected noise (Microsoft). Command lines from events are not shown. Since platform 4.18.26060 a Warn bypass needs administrator approval, which the texts mention. | <https://learn.microsoft.com/en-us/defender-endpoint/attack-surface-reduction-windows-events> |
| R8 | **Security items added:** exploit protection defaults (repair-only: "use default" counts as on through `equivalentOn: ["NOTSET"]`, so nothing is written on a healthy PC; Mandatory ASLR stays at its default), WDigest off (repair-only), no anonymous enumeration, NTLMv2 only (level 5, DISA STIG; Microsoft's minimum countermeasure is level 3), Windows Script Host off (Tier B: Microsoft's documentation is archived, CISA warns some tools use WSH), outbound firewall blocks for mshta/wscript/cscript/regsvr32/certutil (Tier B, MITRE ATT&CK), Print Spooler without inbound clients (Standard) and Print Spooler off (Advanced, only for PCs that never print). | Each item raises security, is anti-cheat safe and fully reversible. |
| R9 | **Not added:** SSDP/UPnP and Teredo off (Xbox networking, party chat and some games' NAT traversal depend on them); WinRM and Remote Registry off (no listener by default / already disabled on Windows 11, so no benefit); mDNS off (undocumented value); USB storage deny and removable-media execute deny (the USB ASR rule covers untrusted programs without breaking USB drives); Office macro policies (per Office version, read-only guidance later); WDAC policies (Lab, deferred); per-app exploit protection templates (deferred: games and anti-cheat react badly to forced mitigations). | Scope rule: only clearly safe and beneficial items, nothing that breaks games or anti-cheat. |
| R10 | **Security score is a read-only weighted checklist** (25 checks, every one with a hint, description and fix route). Pass = weight, Warn = half, Fail = 0; not applicable, Group Policy/MDM-managed and unreadable checks are left out. Smart App Control and Credential Guard are shown but not scored: SAC cannot be turned back on without a reset, and Credential Guard is not part of Windows 11 Pro. | A score must not punish what the user cannot change. |
| R11 | **Network surface lists TCP listeners and UDP endpoints below the dynamic port range (49152+)**, with owning program, services and scope. Listening is not the same as reachable; the firewall decides. Well-known ports and the Print Spooler's dynamic RPC endpoint point to the catalog item that reduces them. | Ephemeral UDP client sockets are noise. |
| R12 | **The cleaner's `Test-IgwtPathUnder` is shared**; a static test now fails when any function name is defined twice, because a later file would silently replace the earlier definition. Another static test refuses `$name?` inside strings (PowerShell reads it as a variable named `name?`). | Static tests guard against both. |

## Expert controls and inspectors (2.0)

| # | Decision | Reason |
|---|---|---|
| X1 | **Inspectors first, edits second.** Six read-only inspectors (power plan, interrupts, network queues, kernel and memory, timer, crash and page file) show current values next to Windows defaults. The only direct editor is the processor power settings editor; every other change goes through a catalog item with its own snapshot and revert. | keeps every write in the audited catalog model. |
| X2 | **Power plan editor scope:** the 16 processor settings in `data\power\processor.json` (EPP, boost mode and policy, min/max state, core parking min cores and concurrency, idle promote/demote, hybrid scheduling policies), level Expert, `-AcknowledgeRisk` or a GUI confirmation, snapshot operation `Power`, revert through `Invoke-IgwtRevert`. Ranges come from what `powercfg /qh` reports on the PC; hardware overlays block settings (core parking and hybrid scheduling on Intel hybrid CPUs, core parking on AMD dual-CCD X3D, battery values on laptops). Processor idle disable is never editable. | Microsoft Learn PPM option pages; overlays H1/H2. |
| X3 | **Defaults:** Windows' stored defaults (`DefaultPowerSchemeValues`) for built-in plans; a plan copy is compared with the built-in plan that has the same name resource. Windows stores no defaults for Ultimate Performance and its hidden base plan reports UNKNOWN, so Balanced is shown as a labelled reference there. | Verified: the Ultimate copy and its base have no stored defaults. |
| X4 | **powercfg output is parsed without labels:** indentation, GUIDs, upper-case aliases and hex values only, so localized Windows works; UNKNOWN indexes are treated as unknown. | Labels are localized; a test uses German-style labels. |
| X5 | **Interrupt edits:** only `gfx.gpu-msi` (Expert, Tier B, reboot, MSISupported = 1 where the driver declares MSI support) is catalogued. On current hardware the GPU, NIC and USB controller usually already use MSI. Affinity policy presets are not catalogued (Microsoft recommends the default policy) and manual core pinning (AssignmentSetOverride) is rejected. The inspector reads the mode in use from the allocated interrupt resources (message-signaled IRQs are reported at 0x80000000 and above). | <https://learn.microsoft.com/en-us/windows-hardware/drivers/kernel/interrupt-affinity-and-priority> |
| X6 | **NIC queues are inspector-only:** RSS placement, queues and buffers with the driver's range and the adapter's discarded-packet counter. Advice to raise receive buffers appears only when packets are actually discarded; the "keep RSS off core 0" advice points to the driver's own setting when it exists (some drivers, such as the Marvell AQtion, do not expose it). | Driver-specific keywords and ranges; evidence before edits. |
| X7 | **The current timer resolution is not displayed.** Reading it needs the undocumented `NtQueryTimerResolution`, which would add a second P/Invoke (same rule as E4/E7). The timer inspector explains the per-process behaviour and points to `powercfg /energy`. | One documented P/Invoke. |
| X8 | **Kernel and memory inspector is read-only:** values are annotated from `data\inspectors\kernel.json` with meaning, default and either the catalog item (the only way to change them) or the rejected entry that explains them. Undocumented values are listed so users can see what other tools changed. | Project scope. |
| X9 | **New System category:** page file managed by Windows (Standard; never disabled, a fixed size is not offered because Microsoft recommends system-managed), small memory dumps (Advanced), verbose status messages (Advanced) and stop-code parameters on the blue screen (Advanced, Tier B: `DisplayParameters` is not documented by Microsoft; source WinUtil with attribution). | <https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/introduction-to-the-page-file>, <https://learn.microsoft.com/en-us/troubleshoot/windows-server/performance/memory-dump-file-options> |
| X10 | **Lab items are rejected, not implemented:** hypervisor launch type off (a BCD write, A1, and it breaks VBS, FACEIT and Vanguard On-Demand), processor idle disable (heat and Raptor Lake voltage risk for no measurable game benefit) and manual interrupt affinity pinning. All are documented in `data\rejected.json` with the other section 6 rejections (test signing and friends, IFEO, registry cleaners, hosts-file blocking, Prefetch cleaning, manual WinSxS/Installer deletion, disabling IPv6). | Scope rule: only clearly safe and beneficial items. |
| X11 | **`power.show-processor-settings` is Advanced, not Expert:** it only clears the hidden attribute so the settings appear in Power Options; values do not change. | Visibility carries no risk. |

## Management and diagnostic modules (2.0)

| # | Decision | Reason |
|---|---|---|
| M1 | **One audited change path.** Services, tasks, inbox apps, optional features, capabilities and app firewall rules change only through `Invoke-IgwtManagedChange`, which turns the request into a synthetic action of an existing, tested type (service, scheduledTask, appx, optionalFeature, capability) or a firewall rule enable flag, writes a snapshot (operation `Manage`) first and reverts through `Invoke-IgwtRevert`.
