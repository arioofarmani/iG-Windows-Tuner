# Firewall Manager: categories, knowledge base and risk rules

> Generated by `tools\Build-Docs.ps1` from `data\firewall\*.json`. Do not edit by hand; validate changes with `tools\Test-FirewallKB.ps1`.

Every firewall rule gets exactly one **origin category**, its **facets** (direction, block) and any **assessments** (bloated, security risks) that apply, each with the reason and a confidence level (High, Medium, Low). Matching uses stable identifiers only (rule IDs, raw group resource strings, package publisher IDs, program paths), never localized display names.

## Origin categories (exactly one per rule)

### Core Services

Built-in rules Windows needs to get an address, find names, use IPv6 and keep its services restricted to the traffic they need. They come from the Core Networking group and the Windows Service Hardening stores. Turning them off breaks the network or weakens Windows' own protection, so the Firewall Manager shows them read-only with the reason each one matters.

- **Criteria:** Rule ID or group in the knowledge base with category CoreServices (Core Networking, @FirewallAPI.dll,-25000; CoreNet-* IDs), Windows Service Hardening rules (StaticServiceStore), and the Windows Security and SmartScreen app rules.
- **Typical members:** CoreNet-DHCP-In, CoreNet-DHCPV6-In, CoreNet-IPv6-In, CoreNet-ICMP6-NDA-In, CoreNet-IGMP-In, CoreNet-DNS-Out-UDP, service hardening rules such as Audiosrv-1.
- **Handling:** Locked: read-only, never disabled or deleted by the Firewall Manager.
- **Sources:** <https://technet.microsoft.com/en-us/library/cc753295> <https://learn.microsoft.com/en-us/powershell/module/netsecurity/set-netfirewallservicefilter>

### Windows Connections

Rules that ship with Windows for features you may or may not use: Cast to Device, Wi-Fi Direct, Remote Assistance, Network Discovery, File and Printer Sharing, remote management, Xbox and the Microsoft Store apps. When a feature is not used on this PC, its rules can be disabled; the feature itself turns them back on when you start using it again.

- **Criteria:** Windows-shipped rules outside Core Services: a Windows group resource string (@FirewallAPI.dll and other system DLLs) or rule ID in the knowledge base, rules from the SystemDefaults store, and AppContainer rules of Microsoft-published packages (publisher IDs 8wekyb3d8bbwe and cw5n1h2txyewy).
- **Typical members:** NETDIS-* (Network Discovery), FPS-* (File and Printer Sharing), PlayTo-* (Cast to Device), RemoteAssistance-*, WMPNSS-*, MCX-*, Microsoft Store app rules.
- **Handling:** Can be disabled when the feature is not used; never deleted.
- **Sources:** <https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules>

### User Installed

Rules created by third-party installers (games, launchers, chat and streaming apps) or automatically when you answered a Windows Defender Firewall prompt; a dismissed prompt creates block rules. Keep the ones for apps you use. Rules whose program no longer exists are orphaned: they can be deleted, because an attacker who drops a file at that path would inherit the rule.

- **Criteria:** A program outside the Windows folder with a non-Microsoft signer or location, the firewall-prompt pattern (GUID rule ID, display name from the program, TCP and UDP pair), or an AppContainer package from a non-Microsoft publisher.
- **Typical members:** Game, launcher and voice chat rules; prompt-created allow and block pairs.
- **Handling:** Keep if the app is installed and used; flagged when orphaned or risky; deletable after a confirmation and a snapshot.
- **Sources:** <https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules>

### Custom Rules

Rules created on purpose: by iG Windows Tuner (rule ID prefix iGWindowsTuner- and its group), by you in the Firewall Manager or in Windows Defender Firewall with Advanced Security, or by an administrator script. Manual rules are recognised by elimination (not Windows, not an app installer, not a prompt), so the confidence is shown.

- **Criteria:** iG Windows Tuner tag (rule ID prefix and group), or a rule that matches no Windows group and no app pattern (heuristic, Medium or Low confidence).
- **Typical members:** iGWindowsTuner-Block-Out-mshta-x64, port rules for a game server, LAN share rules.
- **Handling:** Fully editable and deletable (snapshot first).

## Facets

### Inbound

Inbound rules decide which unsolicited connections reach this PC. Windows blocks inbound traffic by default; every inbound allow rule is an opening, so these are the rules to review first.

- **Criteria:** Direction = Inbound.
- **Typical members:** Game server ports, file sharing, remote desktop.
- **Handling:** Filter view.
- **Sources:** <https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules>

### Outbound

Outbound traffic is allowed by default, so outbound rules mostly block something (for example the script hosts iG Windows Tuner blocks) or allow an app when outbound is set to block.

- **Criteria:** Direction = Outbound.
- **Typical members:** Store app rules, outbound blocks for script hosts.
- **Handling:** Filter view.
- **Sources:** <https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules>

### Blocked

Block rules stop matching traffic even when an allow rule also matches. The view shows each profile's default inbound and outbound action next to the list and highlights blocks that shadow allow rules (the allow never applies).

- **Criteria:** Action = Block.
- **Typical members:** Dismissed firewall prompts, iG Windows Tuner script-host blocks, admin blocks.
- **Handling:** Filter view; blocks that shadow allows are highlighted.
- **Sources:** <https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules>

## Assessments (can overlap)

### Bloated

Rules for features that are not needed for this PC's role (Gamer, Power User, Sysadmin, Workstation), from the knowledge base, plus orphaned rules whose program or package no longer exists. Each one says what stops working when it is disabled. Disabling is reversible; the feature turns its rules back on when you use it.

- **Criteria:** Enabled rule whose knowledge-base entry is 'bloat' for the current role (and whose condition holds, for example the Xbox app is not installed), or an orphaned rule (program or package missing).
- **Typical members:** Media Center Extenders, Windows Media Player Network Sharing, Remote Assistance on a gaming PC, rules of uninstalled apps.
- **Handling:** Recommend Disable, with a 'what stops working' note; orphaned app rules can be deleted.

### Security Risks

Findings from the risk rules in data\firewall\risks.json: wide-open inbound rules, admin and file protocols on Public networks, programs in user-writable folders, unsigned or orphaned programs, script hosts, edge traversal and more. A rule that matches a port something is listening on right now is marked 'Exposed now' and rises one severity level.

- **Criteria:** At least one finding from the risk rules (severity Critical, High, Medium or Low).
- **Typical members:** Any-port inbound allows, RDP or SMB allowed on Public, orphaned program rules.
- **Handling:** Recommend the least invasive fix (restrict to Private, restrict remote to Local Subnet, disable); keep or ignore with a reason.
- **Sources:** <https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules> <https://www.cisa.gov/stopransomware/misconfigurations-and-weaknesses-known-be-used-ransomware-campaigns>

## Security-risk rules
 finding whose rule matches a port something is listening on right now is marked *Exposed now* and rises one severity level.

| Severity | Risk | When | Recommended | Alternatives | Explanation |
|---|---|---|---|---|---|
| Critical | Inbound allow for any program, any port, from anywhere | `enabled` `inbound` `allow` `programAny` `serviceAny` `packageAny` `portAny` `remoteAny` | Disable | RestrictLocalSubnet, RestrictPrivate, Keep, Ignore | This rule allows unsolicited incoming traffic without limiting the program, the port or the remote address. Anything that listens on this PC, including malware or a misconfigured service, is reachable through it. |
| High | Program no longer exists (orphaned rule) | `allow` `orphaned` `nonWindows` | Delete | Disable, Keep, Ignore | The app this rule was made for is gone, but the rule still allows its path. If an attacker places a file with the same name there, it gets the same network access without a prompt. Rules of uninstalled apps can be deleted. |
| High | Remote access or file sharing allowed on Public networks | `enabled` `inbound` `allow` `profilePublic` `ports:adminFile` | RestrictPrivate | RestrictLocalSubnet, Disable, Keep, Ignore | Remote Desktop, file sharing, PowerShell remoting, SSH, VNC and SQL Server are among the most attacked services. Allowing them on the Public profile exposes them on hotel, cafe and airport networks. Keep them to Private (or the local subnet) unless you really connect to this PC over a public network. |
| High | Allow rule for a script host or LOLBin | `enabled` `allow` `scriptHost` | Disable | Keep, Ignore | Script hosts and these signed Windows tools are what attackers use to download and run code ('living off the land'). A rule that explicitly allows them makes that easier, and normal apps do not need one. |
| High | Program without a valid digital signature | `enabled` `allow` `unsigned` | Keep | Disable, Ignore | A signature shows who published a program and that it was not changed since. An allow rule for an unsigned program cannot be traced to a publisher; check that you know the program before keeping the rule. |
| High | Program in a folder any program can write to | `enabled` `allow` `userWritablePath` | Keep | RestrictPrivate, Disable, Ignore | Programs under your user profile (AppData, Temp, Downloads) or the Public folder can be replaced by any process running as you, without administrator rights. A replaced file inherits the firewall rule. Prefer programs installed under Program Files, or remove the rule when the app is not needed. |
| Medium | Windows security rule turned off | `disabledSecurityRelevant` | Keep | Ignore | Windows ships this rule enabled because networking or protection depends on it. Turning it off can break IPv6, DHCP or a security feature. Re-enable it unless you changed it on purpose. |
| Medium | Edge traversal allowed | `enabled` `inbound` `allow` `edgeTraversal` | Keep | Disable, Ignore | Edge traversal lets unsolicited traffic arrive through a NAT router (for example over Teredo IPv6). Games and voice apps sometimes need it for peer connections; other apps rarely do. |
| Medium | Local discovery protocols open on Public networks | `enabled` `inbound` `allow` `profilePublic` `ports:localDiscovery` | RestrictPrivate | Disable, Keep, Ignore | Name and device discovery protocols (NetBIOS 137-139, LLMNR 5355, mDNS 5353, SSDP 1900, WSD) are meant for your own network. On public networks they reveal the PC and LLMNR/NetBIOS answers can be abused to capture credentials. Microsoft is phasing out NetBIOS and LLMNR. |
| Medium | Any remote address where the local subnet would do | `enabled` `inbound` `allow` `localServiceRemoteAny` | RestrictLocalSubnet | RestrictPrivate, Keep, Ignore | File sharing, discovery, casting and remote management are used on your own network. Limiting the remote address to Local Subnet keeps them working at home while refusing connections from further away, as Microsoft recommends for home and small-network services. |
| Low | Very wide port range | `enabled` `inbound` `allow` `broadPortRange` | Keep | Disable, Ignore | Wide port ranges allow far more than an app usually needs. Microsoft recommends being as specific as possible; a program rule (which opens ports only while the program listens) is usually better. |
| Low | Duplicate rule | `duplicate` | Disable | Delete, Keep, Ignore | Two rules with the same direction, action, program, protocol, ports, addresses and profiles. Keeping one makes the list easier to review; the result for your traffic does not change. |
| Low | Rule without a description | `nonWindows` `noDescription` `enabled` | Keep | Ignore | Microsoft recommends documenting every rule (the app, the ports and why) so it can be reviewed later. Add a description, or delete the rule if nobody knows what it is for. |

### Port sets

- **adminFile** (admin and file protocols): TCP 3389, 445, 139, 5985, 5986, 22, 5900, 1433; UDP 3389, 137, 138

## Protected programs
 for these programs are never recommended for blocking; an outbound block on them, or on a game from `data\games.json`, is flagged as *may break online play*.

- **Steam and Valve networking:** Steam downloads, Steam Networking and Steam Datagram Relay carry matchmaking and voice for many games.
- **FACEIT client and anti-cheat:** FACEIT refuses matches when its client or anti-cheat cannot connect.
- **Riot Vanguard and Riot Client:** VALORANT and League of Legends do not start when Vanguard or the Riot Client is blocked.
- **Easy Anti-Cheat:** Games protected by Easy Anti-Cheat kick or refuse players whose anti-cheat cannot reach its servers.
- **BattlEye:** BattlEye-protected games disconnect when BattlEye is blocked.
- **Game launchers:** Launchers handle sign-in, entitlement checks and updates; blocking them breaks online play.
- **Other anti-cheat (Javelin, RICOCHET, EA Anti-Cheat):** Anti-cheat services must reach their servers or the game refuses to start.
